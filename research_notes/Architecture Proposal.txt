1. Initial Retrieval
- User's query
- Retrieve k relevant documents
- Rerank

2. Routing
- An LLM reads all acummulated evidence (across all iterations so far) 
and all queries asked so far, and decides:
+ Can the question be answered using the accumulated evidence?
+ Are there unresolved entities/relationships/information gaps?
+ Would another retrieval step likely provide missing information?
- Outputs: CONTINUE or ANSWER
+ If ANSWER → sufficient evidence → Generate answer
+ If CONTINUE → more retrieval likely useful → Follow-up Retrieval
+ if retrieval is exhausted / insufficient evidence but the model says
CONTINUE → ANSWER but generate answer explicitly stating insufficient 
evidence.

3. Generate Final Answer
- An LLM takes all accumulated evidence and all queries (original + 
follow-ups) and generates the final response.

4. Follow-up Questions & Retrieval
- Generate + select (1 LLM call): an LLM looks at all accumulated 
accpeted documents, the original query, and all previous follow-up 
questions, identifies entities/relationships that are still too 
ambiguous or just straight up missing to answer the user's question, 
generates a small set of candidate follow-up questions about them, and 
picks the single most relevant and informative one.
- Retrieve k document candidates using that question.
- Rerank to get the local relevance score (S_local).

5. Judge (1 batched LLM call)
- A single LLM call reviews all newly retrieved candidates together 
(not one call per document) and outputs YES/NO for each, judging 
whether each candidate contributes useful evidence toward answering 
the original query, either directly or by resolving the information 
gap targeted by the current follow-up question.

6. Filter
- Compute base relevance score for each surviving document:
  S = w · S_global + (1 − w) · S_local
  (S_global = rerank score vs. original query, 
  S_local = rerank score vs. the query that retrieved it)
- Cross-signal trust check: compare the Judge's YES/NO against whether 
S falls above/below the median of the original k documents' scores.
- Signals agree (Judge=YES & S is high, or Judge=NO & S is low) 
→ keep score S as-is.
- Signals disagree → apply a discount factor d (e.g. d = 0.5, tunable) 
to S before filtering.
- Acceptance threshold: compute t_a = mean − c·std_dev from the 
original k documents' scores (step 1), with c ≈ 0.5 as a starting 
point.
- Keep only documents scoring ≥ t_a after the trust-check adjustment.

7. Loop or Stop
After each retrieval iteration, return to Routing. Routing terminates 
when it selects ANSWER, ANSWERNOTENOUGH, or when the maximum depth 
forces termination also through Routing.
